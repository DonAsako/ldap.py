## Why another LDAP library?

I don't care, that's not the point. I just want to make sure I can still code without AI and actually read an RFC lmao.

## Standards

The implementation'll follow the LDAPv3 specification set:

| Document                                           | Scope                                          |
| -------------------------------------------------- | ---------------------------------------------- |
| [RFC 4510](https://www.rfc-editor.org/rfc/rfc4510) | Technical Specification Road Map               |
| [RFC 4511](https://www.rfc-editor.org/rfc/rfc4511) | The Protocol                                   |
| [RFC 4512](https://www.rfc-editor.org/rfc/rfc4512) | Directory Information Models                   |
| [RFC 4513](https://www.rfc-editor.org/rfc/rfc4513) | Authentication Methods and Security Mechanisms |
| [RFC 4514](https://www.rfc-editor.org/rfc/rfc4514) | String Representation of Distinguished Names   |
| [RFC 4515](https://www.rfc-editor.org/rfc/rfc4515) | String Representation of Search Filters        |
| [RFC 4516](https://www.rfc-editor.org/rfc/rfc4516) | Uniform Resource Locator                       |
| [RFC 4517](https://www.rfc-editor.org/rfc/rfc4517) | Syntaxes and Matching Rules                    |
| [RFC 4518](https://www.rfc-editor.org/rfc/rfc4518) | Internationalized String Preparation           |
| [RFC 4519](https://www.rfc-editor.org/rfc/rfc4519) | Schema for User Applications                   |
| [RFC 2696](https://www.rfc-editor.org/rfc/rfc2696) | Simple paged results control                   |
